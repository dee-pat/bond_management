# Bond Management rule-to-test index

This page points from high-risk bond rules to their source modules and existing
regression tests. See [domain-model.md](domain-model.md) for data relationships
and [verification.md](verification.md) for required commands and completion
evidence. Server tests own business rules and permission boundaries; browser
specs cover visible wiring and routing.

Implementation and test paths beginning with `doctype/`, `api/`, `report/`, or
`utils/` are relative to `bond_management/bond_management/`; `patches/`,
`patches.txt`, and `hooks.py` are relative to the app root.

## Coverage gap to track

The repository tests index installation directly and checks duplicate-cleanup
patch ordering, but no regression test was found that runs the complete
registered patch sequence against representative legacy data or exercises the
index `after_install` hook on a fresh site. Permission bootstrap hooks have
separate tests; that coverage does not establish index bootstrap coverage. Use
the fresh-site and migration gates in [verification.md](verification.md) for
those lifecycle paths.
